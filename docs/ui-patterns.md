# Dashboard UI patterns

Use the closest existing flow as the visual reference. Reuse these building blocks before introducing controls or CSS. These patterns retain the existing variants; a tax report table and a portfolio table do not have identical layouts.

- **Choice menus:** Use `src/components/ui/choice-menu.tsx` with the `investment-select` styles for styled choices. Supply an accessible label or `labelledBy`, the selected value, and options. It handles selection, focus restoration, Escape, blur and outside dismissal. Use the `tax-year-select` class for a long report-year list. Native selects wrapped in `select-shell` remain appropriate for existing native controls; do not replace them without checking their keyboard and mobile behavior.
- **Buttons and dialogs:** Use `trade-primary` for a primary action and `trade-buttons` for secondary actions, with `trade-dialog` (and `purchase-dialog` where appropriate) for the existing dialog variants. Use the dashboard control and text color tokens in `dashboard.css` instead of copying their literal values. Preserve disabled, hover and focus states and the existing layout of each flow.
- **Tables:** Use `TableScroll` and `TableHeader` in `src/components/ui/table.tsx` where their markup fits. Portfolio tables use their existing panel styles; reports use `tax-table-wrap`, including its numeric alignment and responsive overflow. Avoid imposing one table layout on both. Keep semantic headings and keyboard-accessible scroll regions.
- **Expandable report rows:** Use `ReportDetails` and the existing `tax-period` / `tax-view-details` styles for report disclosures. Other expandable tables should follow the closest established disclosure pattern.
- **Text and links:** Use existing heading, `text-link`, and page-level patterns. Use `--text-secondary` for the established secondary text color and `--serif` / `--sans` for font families. Do not substitute similar-looking colors or force all labels into one size; those variants carry hierarchy.

Check the existing component and its styles before adding a new variant. Verify the rendered desktop and narrow layouts, keyboard and focus behavior, loading, disabled and error states, and print output where relevant. The dashboard stylesheet still contains page-specific layout and historical overrides; consolidate only after confirming cascade and responsive behavior. The landing page has a separate visual context in `globals.css`.
